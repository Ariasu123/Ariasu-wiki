## Claude Code Compact 机制总结

关联阅读：可结合 [[30-Agent-Engineering-Agent工程/01-Foundations-基础概念/Context_Engineering_10|Context Engineering]] 理解；压缩源码把 Context Engineering 的原则落到状态管理。


Claude Code 的上下文管理目标不只是节省 Token，而是让 Agent 在长任务中仍然保留**用户意图、当前进度、错误经验和任务状态**。
### 一、为什么需要压缩

Agent 比普通聊天更容易撑满上下文：

- System Prompt、工具描述和 `CLAUDE.md` 占用固定空间。
- 每次工具调用都会留下 `tool_use` 和 `tool_result`。
- 文件内容、搜索结果和命令输出通常非常大。
- 历史内容会在后续每轮请求中重复发送。

单纯扩大上下文窗口不能彻底解决成本、延迟和 `Lost in the Middle` （对首尾清楚，对中间模糊）问题。

### 二、五层压缩策略

Claude Code 采用从轻到重的压缩体系：

| 层级  | 策略                   | 处理方式                                                     |
| --- | -------------------- | -------------------------------------------------------- |
| 1   | 大结果存磁盘               | 单个工具结果超过约 50KB 时，完整内容存盘，上下文只留约 2KB 预览                    |
| 2   | Snip                 | 由模型标记已经无用的早期消息，再在本地删除                                    |
| 3   | Micro-Compact        | 清理可重新获取的旧工具结果，只保留最近若干条，子 agent 输出、Task 状态这类「不可重复」的结果绝不裁剪 |
| 4   | Context Collapse读时投影 | 不修改原始历史，只在调用 API 时生成压缩视图                                 |
| 5   | Auto-Compact全量摘要     | 将全部历史重写为结构化摘要，并恢复关键状态                                    |

其中 `Context Collapse` 和 `Auto-Compact` 是互斥方案，并不会同时执行。前者属于实验特性，公开版本主要使用 Auto-Compact，**只能2选1。

### 三、Auto-Compact 的触发

它不按轮数或时间触发，而是根据绝对 Token 阈值：

```
原始上下文窗口
- 约 20K 摘要输出空间
- 约 13K 安全缓冲
= 压缩触发线
```

也就是距离原始窗口上限约 33K Token 时开始压缩，保证摘要本身仍有生成空间。

### 四、全量重写

Auto-Compact 不保留“最近 N 条消息”，而是**将所有历史消息重新总结**。压缩后的消息链由四部分组成：

1. **边界标记**：记录压缩方式（是自动触发/用户输入）、压缩前 Token 数和消息位置。
2. **结构化摘要**：保存任务的语义信息。
3. **附件**：恢复文件、计划、Skill 和异步任务状态。
4. **Hook 结果**：注入压缩期间执行的 Hook 信息。

其核心思想是区分两类信息：

- **语义信息**：用户意图、技术决策、错误和待办，进入摘要。
- **精确状态**：文件内容、任务进度和计划，通过附件原样恢复。

### 五、关键内容如何恢复

- 最近读取的文件最多恢复 **5 个**。
- 每个文件最多约 **5K Token**。
- 文件恢复总预算最多约 **50K Token**。
- `CLAUDE.md` 不进入摘要，而是清除缓存，下一轮重新从磁盘加载。
- System Prompt 不压缩，而是在压缩完成后重新构建。
- 后台子 Agent 的运行状态通过**附件恢复。

### 六、摘要 Prompt

摘要要求模型按照九个部分输出，包括：

- 用户主要请求和意图
- 关键技术概念
- 涉及的文件和代码
- 错误与修复方法
- 问题解决过程
- **所有用户消息**
- 待完成任务
- **当前工作状态**
- 下一步建议

特别要求不能遗漏用户消息，并且要把“当前正在做什么”精确到文件、函数和具体进度。

### 七、压缩后的接续

```
生成摘要
→ 清理旧缓存
→ 并行恢复附件
→ 组装新的消息链
→ 替换旧历史
→ 继续执行
```

摘要会明确告诉模型：这是一次旧会话的延续，而不是新任务。自动压缩时还会禁止摘要产生新的追问，避免打断正在运行的任务。

**核心结论：Claude Code 的 Compact 不是简单删除历史，而是将不同类型的信息分流管理，用“语义摘要 + 状态恢复 + 永久信息重载”保证 Agent 可以继续工作。**
