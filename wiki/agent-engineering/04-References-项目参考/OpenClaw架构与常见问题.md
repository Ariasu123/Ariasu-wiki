
## 1. 什么是 OpenClaw？

关联阅读：可结合 [Loop Engineering](../03-Harness-and-Workflows-%E8%BF%90%E8%A1%8C%E6%A1%86%E6%9E%B6%E4%B8%8E%E5%B7%A5%E4%BD%9C%E6%B5%81/Loop%20Engineering.md) 理解；Loop Engineering 可用于分析 OpenClaw 的运行可靠性。OpenClaw 作为执行集群层（L1）接入组织级认知系统的架构见 [从 Prompt 到 Harness：企业级 Agent 工程演进（千问 AI 平台）](../03-Harness-and-Workflows-%E8%BF%90%E8%A1%8C%E6%A1%86%E6%9E%B6%E4%B8%8E%E5%B7%A5%E4%BD%9C%E6%B5%81/%E4%BB%8E%20Prompt%20%E5%88%B0%20Harness%EF%BC%9A%E4%BC%81%E4%B8%9A%E7%BA%A7%20Agent%20%E5%B7%A5%E7%A8%8B%E6%BC%94%E8%BF%9B%EF%BC%88%E5%8D%83%E9%97%AE%20AI%20%E5%B9%B3%E5%8F%B0%EF%BC%89.md)。


OpenClaw 是一个运行在个人电脑或服务器上的自主 AI Agent，可以长期在线并操作真实设备完成任务。

普通大模型只有“语言大脑”，OpenClaw 为它补充了执行能力、长期记忆、通信入口和主动运行机制。其核心架构包括：

- **Gateway**：鉴权、会话管理和请求路由。
- **Agent**：理解目标、规划步骤并跟踪执行。
- **Tools**：文件读写、终端命令、API 调用等原子能力。
- **Skills**：将多个工具组合成完整任务流程。
- **Channels**：接入飞书、微信、Telegram 等通信平台。
- **Nodes**：连接电脑、手机等设备，提供本地控制能力。

## 2. OpenClaw 的核心亮点是什么？

主要有六点：

1. **多平台接入**：可以通过日常通信软件远程下达任务。
2. **本地执行能力**：能够操作文件、终端、浏览器和桌面应用。
3. **技能扩展**：通过 Skill 持续增加新的任务能力。
4. **主动工作**：利用心跳和定时任务实现全天候巡检。
5. **自我修正**：执行失败后分析原因、调整方案并重新尝试。
6. **永久记忆**：把用户偏好、项目状态和历史经验保存到本地。

## 3. OpenClaw 的文件目录结构是怎样的？

OpenClaw 采用“文件即 Agent”的设计，核心工作空间主要包含：

| 文件或目录              | 作用                    |
| ------------------ | --------------------- |
| **`SOUL.md`**      | 定义 Agent 的性格、价值观和表达风格 |
| **`AGENTS.md`**    | 记录任务流程、行为规范和操作边界      |
| `TOOLS.md`         | 注册可用工具和技能             |
| **`HEARTBEAT.md`** | 保存**定时巡检和主动任务**清单     |
| **`MEMORY.md`**    | 保存提炼后的**长期记忆**        |
| `sessions/`        | 按日期保存**短期对话和执行日志**    |

这些文件都是可读、可修改的 Markdown，可以进行版本管理，也方便迁移和分享。

## 4. OpenClaw 与传统 Agent 有什么区别？

|维度|传统 Agent|OpenClaw|
|---|---|---|
|运行方式|用户触发，被动响应|后台常驻，主动巡检|
|执行环境|多为云端或沙箱|本地优先，直连设备|
|权限范围|权限受限|可读写文件、执行命令和控制软件|
|记忆方式|跨会话容易丢失或不可见|本地文件保存，透明可编辑|
|产品定位|面向单一场景|通用 AI 执行基础设施|
|交互入口|独立网页或应用|可接入日常通信平台|

核心差异是：传统 Agent 通常是“叫一下动一下”，OpenClaw 更像长期在线的本地数字助理。

## 5. OpenClaw 的记忆机制怎么实现？

它采用 **Markdown + SQLite** 的混合记忆方案：

1. **短期记忆**  
    当前对话和执行记录保存在 `sessions/` 中，启动时只加载最近内容。
    
2. **长期记忆提炼**  
    **对话快达到上下文上限时，模型会总结重要事实**、用户偏好和任务经验，写入 `MEMORY.md`。
    
3. **建立检索索引**  
    `MEMORY.md` 的内容会被切分、**向量化**，并存入带向量搜索能力的 SQLite。
    
4. **双路召回**  
    新任务到来时，同时使用向量相似度和 BM25 关键词检索相关记忆。
    
5. **注入上下文**  
    只把最相关的记忆片段放入当前 Prompt，而不是加载全部历史。

这种设计兼顾了机器检索效率和人类可读性，**记错时可以直接编辑 `MEMORY.md`。

## 6. OpenClaw 解决了什么痛点？

主要解决三个问题：

1. **大模型无法落地执行**  
    普通模型只生成代码或命令，用户还要手动执行；OpenClaw 可以自己运行、读取错误日志并继续修复。
    
2. **跨会话失忆**  
    用户偏好、代码规范和项目进度会保存到本地，不需要每次重新说明。
    
3. **工具切换繁琐**  
    用户可以直接在聊天软件中下达任务，后台设备完成后自动返回结果。

它解决的本质问题是：把“回答问题”推进到“真正完成任务”。

## 7. OpenClaw 有什么缺点？

主要有三个：

1. **安全风险高**  
    本地文件和终端权限过大时，模型幻觉、误操作和 Prompt 注入可能造成文件删除或隐私泄露。生产使用需要沙箱、权限白名单和危险操作确认。
2. **Token 成本高**  
    **心跳**、自我反思、**失败重试**、**记忆总结**和长 Prompt 都会持续消耗 Token。
3. **依赖设备在线**  
    本地电脑或服务器必须保持开机联网，否则无法执行心跳和接收远程任务。

## 8. Coze、n8n 和 OpenClaw 有什么区别？

|产品|定位|特点|
|---|---|---|
|Coze|云端低代码 Agent 平台|搭建简单、发布方便，但本地权限有限|
|n8n|自动化工作流平台|流程确定、稳定可控，但依赖预设节点和条件|
|OpenClaw|本地自主 Agent|能动态规划、操作设备、试错和自我修正|

简单理解：

- **Coze**：云端 Agent 搭建平台。
- **n8n**：按照固定规则运行的自动化流水线。
- **OpenClaw**：可以根据目标和执行反馈动态调整计划的本地 Agent。

## 9. 为什么 OpenClaw 特别烧 Token？

主要有四个原因：

1. **心跳机制**  
    每次定时唤醒都要加载**人设、规则、工具清单和任务列表**，即使没有任务也会产生输入 Token。
    
2. **反思和重试**  
    执行失败后会读取日志、分析原因、生成方案并重新执行，每轮都会累积上下文。
    
3. **记忆管理**  
    长对话需要总结压缩，后续任务还要检索并注入历史记忆。
    
4. **基础 Prompt 很长**  
    `SOUL.md`、`AGENTS.md`、工具定义等内容可能需要随任务一起发送。


因此，成本优化通常需要限制心跳频率、最大重试次数、上下文长度和高价模型使用范围。
