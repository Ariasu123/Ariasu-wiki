
**短期记忆在会话中实现**，下面讲的都是长期记忆
Claude Code 使用“**结构化 Markdown 文件 + LLM 筛选**”实现**长期记忆**，不依赖向量数据库，整体分为静态记忆和动态记忆两层。

与之相比，[ByteRover](../../04-References-%E9%A1%B9%E7%9B%AE%E5%8F%82%E8%80%83/ByteRover.md) 把记忆独立为跨 Coding Agent 复用的 Context Tree，并增加全文检索、知识生命周期、Review 和版本工作流；代价是需要额外 CLI、Daemon 与知识治理。

### 1. 静态记忆：CLAUDE.md

关联阅读：可结合 [Context Engineering](../../01-Foundations-%E5%9F%BA%E7%A1%80%E6%A6%82%E5%BF%B5/Context%20Engineering%20%E9%9D%A2%E8%AF%95%2010%20%E9%97%AE.md) 理解；长期记忆与短期上下文共同构成信息生命周期。


用于保存明确、稳定的协作规则，共有六个层级：

|层级|作用|
|---|---|
|Managed|企业或管理员强制规则|
|User|用户跨项目的全局偏好|
|Project|项目共享规则，可提交 Git|
|Local|个人项目规则，通常不提交|
|Auto|Claude 自动学习的项目记忆|
|Team|团队共享的自动记忆|

各层内容是**叠加加载**，不是相互覆盖，最终共同注入 System Prompt。

它还支持：

- `@include`：引用其他规则文件。
- `.claude/rules/`：根据文件路径按需加载规则。
- 行数（200行）和字节数（25KB）双重截断：避免记忆索引撑爆上下文。

### 2. 动态记忆：四种类型

Claude Code 只允许保存四类记忆：

- `**user**`：用户背景、能力和知识水平。
- `feedback`：用户偏好、反感行为和有效实践。
- `project`：项目决策、期限和当前动态。
- `reference`：外部系统、文档和信息入口。

其中 `feedback` 和 `project` 要记录：

```
事实或规则
为什么如此
应该如何应用
```

项目中的相对日期还要转换为绝对日期。

### 3. 不应该保存的内容

以下信息通常不进入记忆：

- 代码结构、文件路径和实现细节
- Git 历史和最近改动
- 调试过程与修复方案( fix 已经在代码里，commit 已经记录了上下文）
- 已经写在 `CLAUDE.md` 中的内容
- 临时任务状态和当前会话内容

原则是：**能够从代码、Git 或现有文件重新获取的信息，不存入长期记忆。**

### 4. 存储结构

每条记忆是一个独立的 Markdown 文件，并包含 YAML 元信息：

```
---
name: no_mock_database
description: 用户要求数据库测试使用真实环境
type: feedback
---
```

`MEMORY.md` 只保存记忆索引，并常驻 System Prompt；完整记忆文件只在真正需要时加载。

```
MEMORY.md：告诉 Agent 有哪些记忆
独立 Markdown：保存每条记忆的完整内容
```

### 5. 自动写入

每轮主任务结束后，**`stopHook` 会触发独立的 `extractMemories` 代理：

1. **fork复用主会话及 Prompt Cache。
2. 检查用户的纠正、偏好和项目事实。
3. 与已有记忆比较，避免重复。
4. 判断是否值得长期保存。
5. 分类后写入独立 Markdown 文件。
6. 更新 `MEMORY.md` 索引。

记忆抽取在后台完成，不干扰主 Agent 的任务执行。

### 6. 记忆召回

新请求到来时，系统会：

1. 读取所有记忆文件前约 30 行，提取元信息。
2. 将记忆标题、描述和类型交给 Sonnet。
3. 让 Sonnet 最多选择 5 条真正相关的记忆。
4. 再读取这些记忆的完整内容。
5. 使用 `<system-reminder>` 注入当前会话。

**两层过滤**：
已经在当前对话出现过的记忆会被过滤，避免反复注入。正在使用某个工具时，也不会重复加载普通的工具说明，但仍会保留相关警告和已知问题。

### 7. 老化与验证

**较旧的记忆会附带时间警告**，提醒模型它可能已经过时。

使用涉及代码状态的记忆前，Agent **应重新验证**：

- 文件路径是否仍然存在
- 函数或配置项是否仍然有效
- 当前代码是否已经发生变化

**完整闭环：**

```
对话结束
→ 后台抽取记忆
→ 分类并写入 Markdown
→ 更新 MEMORY.md
→ 新会话由 Sonnet 筛选
→ 按需加载完整记忆
→ 注入上下文并验证时效性
```
