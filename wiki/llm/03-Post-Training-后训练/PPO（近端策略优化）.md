## 一、PPO 在 RLHF 中扮演什么角色

RLHF 中常见的 PPO 训练一般包含四个模型：

| 模型 | 是否训练 | 作用 | 常见初始化 |
| --- | --- | --- | --- |
| Actor Model | 是 | 负责生成回复，是最终要优化的策略模型 | 用 SFT 模型初始化 |
| Critic Model | 是 | 预测当前回复的期望收益 $V$ | 通常在骨干模型上加 Value Head |
| Reward Model | 否 | 对完整回复打分，提供奖励 $R$ | 预训练好的奖励模型 |
| Reference Model | 否 | 作为 KL 约束基准，防止策略跑偏 | 冻结的初始 SFT 模型 |

### 1. Actor Model

- 策略模型，直接负责生成回复。
- 输入通常是用户 query 或对话上下文。
- 训练时会根据生成结果的奖励、优势和策略损失来更新参数。

### 2. Critic Model

- 价值模型，用来估计“这次回复大概值多少分”。
- 它不直接生成文本，而是输出期望收益 $V$。
- 后续通过 $A = R - V$（或 GAE 版本）判断当前生成是超预期还是低于预期。

### 3. Reward Model

- 奖励模型，负责给完整回答打最终分数。
- 它提供的是“结果好不好”的监督信号，而不是“每一步怎么走”。

### 4. Reference Model 与 Old Actor

- **Old Actor**：当前更新开始前的 Actor 快照，用来和当前 Actor 计算概率比值 `ratio`，控制单步更新幅度。
- **Reference Model**：冻结的初始 SFT 模型，用来计算 KL 惩罚，防止模型只会迎合 Reward Model。

### 5. 为什么 PPO 强调“近端”

- **近端（Proximal）** 的意思是：每次只允许策略做小步更新。
- 具体依靠两种机制实现：
  - `clip`：避免当前策略 $\pi$ 与旧策略 $\pi_{old}$ 差太多
  - `KL penalty`：避免当前策略偏离参考策略 $\pi_{ref}$ 太远

## 二、minimind-ppo 的训练流程拆解

### Step 1. RL 数据处理

- 通过 `i % 2 == 0` 的奇偶校验，把对话规范成 `User -> Assistant -> User -> Assistant` 的交替格式。
- 切掉最后一轮参考答案，把它保留在监督侧，不直接喂给 Actor。
- 只把前面的上下文当作 Prompt 输入，并开启 `add_generation_prompt=True`，让 Actor 自己生成答案。

> [!tip]
> 这一步的目标是把样本改造成“给定 Prompt，由策略自己采样回答”的 PPO 训练格式。

### Step 2. 混合奖励结算

生成完成后，由奖励系统对整段回复打分。复杂推理模型常用 **Hybrid Reward**。

#### 2.1 规则奖励（Rule-based）

- 检查输出格式是否满足约束，例如是否符合 `<think>...</think><answer>...</answer>`。
- 满足格式给基础分，不满足则扣分。
- 这类奖励适合做冷启动阶段的强约束。

#### 2.2 模型奖励（Neural-based）

- 由 Reward Model 从语义质量上打分，例如逻辑性、有用性、安全性。

#### 2.3 最终奖励

- 将格式分与质量分加权，得到最终全局奖励 $R$。

### Step 3. 价值评估与优势计算

拿到最终奖励 $R$ 后，还要判断这次回答是“高于预期”还是“低于预期”。

#### 3.1 Critic 给出价值估计

- Critic 输出当前回答的期望收益 $V$。

#### 3.2 计算优势

$$
A = R - V
$$

- $A > 0$：实际表现好于预期，应提高这类生成的概率。
- $A < 0$：实际表现差于预期，应降低这类生成的概率。

> [!note]
> 在实际实现里，也常用 GAE 对优势做平滑，降低方差、让训练更稳定。

### Step 4. PPO 的两层稳定器

#### 4.1 Clip：限制单步更新幅度

- 先计算当前策略与旧策略的概率比值：

$$
r(\theta) = \frac{\pi_{\theta}(a|s)}{\pi_{\theta_{k}}(a|s)}
$$

- 再通过 `torch.clamp` 把它限制在 $[1-\epsilon, 1+\epsilon]$。

**直觉：**
- 就算这次回答特别好，也不允许一次把参数改得过猛。
- 这样能防止策略坍塌或训练震荡。

#### 4.2 KL Penalty：限制偏离参考模型

- 计算当前 Actor 与 Reference Model 之间的 KL 散度。
- 若偏离太大，就增加惩罚。

**直觉：**
- Actor 可以变强，但不能为了刷奖励而完全偏离原始 SFT 的语言风格和基本能力。

## 三、训练时最终优化什么

PPO 最终反向传播的总损失通常写成：

$$
\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{policy}} + c_{1} \mathcal{L}_{\text{value}} + c_{2} \mathcal{L}_{\text{KL}}
$$

### 1. 策略损失 $\mathcal{L}_{\text{policy}}$

- 结合 Advantage 和 Clip，指导 Actor 朝高奖励方向稳定更新。

### 2. 价值损失 $\mathcal{L}_{\text{value}}$

- 让 Critic 的预测值 $V$ 逐步逼近真实奖励，提高价值估计质量。

### 3. KL 惩罚 $\mathcal{L}_{\text{KL}}$

- 作为安全护栏，限制策略偏离参考模型。

## 四、关键概念补充

### 1. 重要性采样（Importance Sampling）

#### 核心背景

- 最基础的策略梯度是 **On-policy**：采样一次、更新一次，旧数据随后作废。通过**重要性采样**，PPO 允许利用旧策略产生的数据来更新新策略，具备了 Off-policy 的数据复用能力
- PPO 为了提高数据利用率，会复用旧策略采样得到的数据。
- 这时就要通过重要性采样修正“数据分布不一致”的问题。

#### 关键数学量

- **$s$ 或 $x$**：状态（State）。在 NLP 中通常是 Prompt 加上当前时刻之前已生成的 Token。
- **$a$ 或 $o$**：动作（Action / Output）。可以理解为当前生成的 Token 或整段回答。
- **$\pi_{\theta}(a|s)$**：当前策略（New Policy）。
- **$\pi_{\theta_{k}}(a|s)$ / $\pi_{old}$**：旧策略（Old Policy）。
- **$r(\theta)$**：重要性采样比率

$$
r(\theta) = \frac{\pi_{\theta}(a|s)}{\pi_{\theta_{k}}(a|s)}
$$

#### 它解决什么问题

- 数学上：把“旧策略采样的数据”转换成“可用于当前策略更新”的估计量。
- 工程上：允许一批采样数据被重复利用，而不是每更新一次就丢掉。

### 2. PPO 裁剪（Clip）

#### 核心背景

- 如果 $r(\theta)$ 波动太大，策略更新就可能失控。
- PPO 通过裁剪机制限制更新幅度。

#### 关键数学量

- **$\epsilon$**：裁剪阈值，常见取值是 0.1 或 0.2。
- **$A_{t}$**：优势函数（Advantage）。
- **$clip(r(\theta), 1-\epsilon, 1+\epsilon)$**：把比率限制在稳定区间内。

#### 直觉理解

- 如果 **$A > 0$**，说明动作表现好，模型会倾向增大它的概率，但最多增到 $1+\epsilon$。
- 如果 **$A < 0$**，说明动作表现差，模型会倾向减小它的概率，但最少减到 $1-\epsilon$。
- 结果就是：能更新，但不能乱跳。

### 3. KL 散度（KL Divergence）

#### 核心背景

- KL 散度用来衡量两个概率分布是否接近。
- 在 RLHF 中，它负责约束当前策略不要偏离参考模型太远。

#### 关键数学量

- **$\pi_{ref}$**：参考模型（Reference Model）。
- **$\beta$ / $\eta$**：KL 惩罚系数，用来平衡奖励与约束强度。
- **$D_{KL}(\pi_{\theta} \parallel \pi_{ref})$**：当前策略与参考策略的差异度量。

#### 常见 KL 估计量

1. **K1**： $-\log r$
   - 无偏，但方差大，而且可能出现负值，训练波动更明显。
2. **K2**： $\frac{1}{2}(\log r)^{2}$
   - 恒为正，数值更稳定，但它是有偏估计。
3. **K3**： $r - 1 - \log r$
   - 无偏、恒大于 0，且方差更低。
   - 在 GRPO 和现代 PPO 实现里更常见。
