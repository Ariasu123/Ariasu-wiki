### 1. 核心思想：大模型的“本征维度”假说

关联阅读：可结合 [SFT 监督微调](SFT%20%E7%9B%91%E7%9D%A3%E5%BE%AE%E8%B0%83.md) 理解；LoRA 常用于降低 SFT 的可训练参数量和显存成本。


在理解 LoRA 之前，我们要先明白为什么它可以起作用。

大模型动辄拥有数百亿（如 70B）参数。按照传统的**全参数微调（FFT）**，我们需要计算并更新这几百亿个参数的梯度，这需要极其庞大的显存（尤其是优化器状态，比如 Adam 需要保存一阶和二阶动量，显存占用是模型参数本身的数倍）。

但微软的研究人员在提出 LoRA 时，基于一个重要的假设：**“过度参数化的模型驻留在一个较低的本征维度（Intrinsic Dimension）上”**。

通俗地理解：大模型就像一本包含了全人类知识的《大英百科全书》（预训练权重）。现在你要教它做一道具体的数学题（SFT）。你不需要把整本百科全书重写一遍，你只需要在旁边贴一张“小纸条”**，写上解这道题的关键思路。这张“小纸条”，就是 LoRA。大模型在特定任务上的“改变”，其实并不需要满秩（Full-rank）的参数更新。

### 2. 数学原理：矩阵分解

LoRA 的核心操作是：**冻结预训练模型的原有权重，在旁边挂载一个由两个小矩阵相乘构成的“旁路（Bypass）”**。
![](../_assets/Pretraining-%E9%A2%84%E8%AE%AD%E7%BB%83/LoRA%E7%BB%93%E6%9E%84.png)

假设预训练模型中某一个全连接层（比如 Attention 层中的 Query 投影矩阵）的权重矩阵为 $W_0 \in \mathbb{R}^{d \times k}$，输入为 $x$ 在没有微调时，前向传播是：
$$h = W_0 x$$
如果我们进行全参数微调，权重会产生一个更新量 $\Delta W$。微调后的前向传播变成：

$$h = (W_0 + \Delta W) x = W_0 x + \Delta W x$$

LoRA 的神来之笔就在于对 $\Delta W$ 的处理。既然大模型的改变发生在低维空间，那么我们就强行用两个低秩（Low-Rank）的小矩阵相乘来近似逼近这个庞大的 ΔW：

$$\Delta W \approx B A$$

- **降维矩阵 $A$**：维度是 $r \times k$，负责把高维特征降到极低的维度 $r$。
    
- **升维矩阵 $B$**：维度是 $d \times r$，负责把低维特征重新映射回高维。
    
- **秩 $r$（Rank）**：这是一个超参数（通常设为 8, 16, 64 等），且 $r \ll \min(d, k)$。
    

此时，引入 LoRA 后的前向传播变成了：

$$h = W_0 x + B A x$$

在训练过程中，$W_0$是完全冻结的（不需要计算梯度，也不保存优化器状态），**我们只训练矩阵 A 和矩阵 B**。因为 r 非常小，需要训练的参数量瞬间下降了 1000 倍甚至 10000 倍！

### 3. 初始化策略

这是 LoRA 能够成功训练的数学基石。如果在第 0 步时处理不好，模型要么由于噪声过大瞬间崩溃（Loss Shock），要么梯度完全锁死无法更新。LoRA 巧妙地采用了**不对称初始化**策略：

1. **矩阵 $B$：强制全零初始化（Zero）。**
    
    - **作用：** 保证在训练最开始的第 0 步，旁路输出必定为 0（即 $BAx = 0$）。此时模型的总输出完全等于原基座模型（$h = W_0 x$），实现了**无损接入**，模型不会因为突然加上了外挂矩阵而“发疯”。
    
2. **矩阵 $A$：随机高斯分布初始化（Gaussian）。**
    
    - **作用：** 如果 A 和 B 全是 0，根据反向传播链式法则，A 和 B 互为对方的系数，计算出的梯度将永远是 0，参数彻底锁死。通过给 A 注入随机高斯噪声，保证了输入经过 A 后产生非零激活（$Ax \neq 0$）。这样在第一步反向传播时，**B 就能获得非零梯度并率先开始更新**。随着 B 不再为零，A 也会在后续步骤中被激活，两者开始愉快地协同进化。

这意味着初始状态下，$h = W_0 x + 0 = W_0 x$。带 LoRA 的模型与原版基座模型的输出**完全一模一样**，实现了平滑过渡。随着训练的进行，$B$ 逐渐获得非零梯度，旁路才开始发挥作用。

### 4. 缩放因子（Scaling Factor）

在真实的 LoRA 代码实现中（如 HuggingFace 的 PEFT 库），旁路的输出还会乘以一个缩放因子：$\frac{\alpha}{r}$

完整的公式其实是：

$$h = W_0 x + \frac{\alpha}{r} B A x$$
- **作用：** 这个缩放因子的作用类似于学习率的调节器。当我们在实验中尝试不同的秩 r 时，拥有这个缩放因子可以帮助我们保持训练的稳定性，不需要每次改 r 都去重新痛苦地调整学习率（Learning Rate）。通常建议将 α 设置为 r 的 1 倍或 2 倍（例如 r=8,α=16）。
###  5. 目标模块与超参数选择

结合原论文的消融实验，我们在真实使用 HuggingFace `peft` 库等工具配置 `LoraConfig` 时，应遵循以下工业界公认的铁律
![](../_assets/Pretraining-%E9%A2%84%E8%AE%AD%E7%BB%83/LoRA%E5%BA%94%E7%94%A8%E7%9F%A9%E9%98%B5%E4%B8%8E%E6%9C%80%E4%BD%B3r%E5%80%BC.png)

#### 1. 挂载位置：广度优先

在可训练参数量受限的情况下，**尽可能把 LoRA 挂在更多的层上，即使每个层的秩 $r$ 设得很小，也远比在一个层上设置巨大的 $r$ 效果更好。**

- **算力极其贫瘠：** 至少挂载 Attention 的 Query 和 Value（`target_modules=["q_proj", "v_proj"]`）。
    
- **常规主流微调：** 挂满 Attention 的四大核心矩阵（`["q_proj", "k_proj", "v_proj", "o_proj"]`）。
    
- **注入大量垂直领域新知识：** 强烈建议挂载所有线性层，包括 MLP 层（`target_modules="all-linear"`）。因为 Attention 负责信息路由，而 MLP 才是大模型存储世界知识的核心记忆库。

#### 2. 秩 $r$ 的选择

打破“参数越大越好”的迷思。实验证明，对于大部分格式微调、语气模仿任务，由于其“本征维度”极低，**$r=4$ 或 $r=8$ 已经逼近性能极限**。盲目开到 64 甚至 128 不仅浪费显存，还容易引发过拟合。

- **例外情况：** 只有当下游任务与预训练任务差异极大（如跨语言微调、注入全新的代码库/医疗私有知识）时，才需要适当调大 $r$（如 16, 32, 64），为模型扩充“脑容量”。
