## 1. 什么是大语言模型？和传统 NLP 模型有什么区别？

### 核心回答

大语言模型是用海量语料预训练、参数规模达到百亿甚至千亿级、**以“预测下一个 token”为核心目标的生成式模型**（自回归+因果淹码）。它和传统 NLP 最大的区别是：**传统 NLP 往往是“一任务一模型”，而 LLM 用一个统一的生成式模型，通过 Prompt 表达不同任务。**
### 细节

- 传统 NLP：分词、情感分析、命名实体识别、问答等任务通常分别训练模型。
- BERT 时代：进入“预训练 + 微调”范式，但下游任务仍需单独适配。
- LLM 时代：把任务统一成文本输入和文本输出，靠 Prompt 描述任务。
- **传统 NLP 多是判别式模型，输入文本后输出标签或概率。
- LLM 是生成式模型，输入文本后继续生成文本。
- LLM 规模足够大后，会出现上下文学习、多步推理、跨语言迁移等**涌现能力。**
### 面试提醒

不要只背定义。回答时要突出范式变化：从“一任务一模型”变成“一个模型 + Prompt 承接多任务”，从判别式走向生成式。

## 2. Transformer 架构基本原理是什么？Encoder 和 Decoder 是什么？

### 核心回答

Transformer 的核心创新是**Self-Attention，让每个 token 都能直接和序列中任意位置的 token 建立联系，并且可以并行计算**。Encoder 更适合理解任务，Decoder 更适合生成任务，现代主流大模型大多采用 Decoder-only 架构。
### 细节

- RNN 的问题：顺序计算难并行，长距离依赖容易衰减。
- Self-Attention 的做法：**每个 token 通过 Q、K、V 计算对其他 token 的注意力权重，再加权聚合信息。
- `Q` 表示“我想找什么”，`K` 表示“我有什么特征”，`V` 表示“我真正提供的信息”。
- 输入 embedding 通过**三个独立的线性投影矩阵** W_Q、W_K、W_V 算出来
- **「除以 √d_k 是为了防止点积过大让 softmax 变 one-hot 导致梯度消失」

---
- Encoder 是双向注意力，每个 token 可以看前后文，适合理解任务。
- Decoder 是单向注意力，只能看前面的 token，适合自回归生成。
- **Decoder-only 胜出的关键是训练目标统一：预测下一个 token，可直接利用海量无标注文本，并且随着模型规模增大，这个简单目标下涌现出的能力越来越强**
### 面试提醒

讲 Transformer 时先讲为什么 RNN 不够，再讲 Self-Attention 如何解决并行和长距离依赖问题。最后补一句为什么 GPT、Qwen、Llama 等主流 LLM 多用 Decoder-only。

## 3. MHA 有哪些局限？MQA、GQA、Flash Attention 怎么解决？

### 核心回答

**MHA 的主要痛点是 KV Cache 显存占用大、Attention 计算访存慢、长序列下复杂度高。MQA 和 GQA 从结构层减少 K/V 数量，Flash Attention 从实现层减少显存读写和中间矩阵开销**。
### 细节

| 技术                  | 核心思路                  | 解决问题                                   | 代价           |
| ------------------- | --------------------- | -------------------------------------- | ------------ |
| MHA                 | 每个 head 独立 K/V        | 表达能力强                                  | KV Cache 显存大 |
| MQA                 | 多个 head 共享一份 K/V      | 大幅减少 KV Cache                          | 表达能力可能下降     |
| GQA                 | 多个 head 分组共享 K/V      | 在 MHA 和 MQA 之间折中                       | 实现稍复杂        |
| **Flash Attention** | **分块计算 + 在线 softmax** | 减少 HBM 读写，在SRAM里计算小块，显存从 O(N²) 降到 O(N) | 依赖优化 kernel  |

GQA 是当前很多主流模型的甜蜜点，Flash Attention 不改变模型结构，而是优化计算实现。两者可以叠加。
### 面试提醒

一句话抓重点：MQA/GQA 是结构层优化，Flash Attention 是实现层优化，主流推理栈通常会一起用。

## 4. 位置编码是干什么用的？sin/cos、RoPE、ALiBi 有什么区别？

### 核心回答

Self-Attention 本身是“位置盲”的，不知道 token 的顺序。**位置编码用于把位置信息注入模型**，让模型区分“我打你”和“你打我”。主流方案包括 sin/cos 绝对位置编码、RoPE 旋转位置编码、ALiBi 线性距离惩罚。
### 细节

| 方案      | 思路                               | 优点              | 缺点                  |
| ------- | -------------------------------- | --------------- | ------------------- |
| sin/cos | 给每个**绝对位置**生成固定向量并加到 embedding 上 | 简单、无训练参数        | 长上下文**外推差**，绝对位置较死板 |
| RoPE    | **旋转 Q/K，把相对位置信息写入点积**           | 相对位置建模好，长上下文扩展强 | 需要配合扩展技巧和校准         |
| ALiBi   | 在 attention 分数中加入距离惩罚            | 简单、零参数、外推好      | 表达力弱于 RoPE          |

RoPE 在相对位置建模、长上下文扩展和工程兼容性之间比较均衡，因此被 Llama、Qwen、DeepSeek 等主流模型大量采用。

YaRN 是一种 RoPE 长上下文扩展方法。它的核心不是简单把所有 position 线性缩放，而是根据 **RoPE 不同频率维度进行分段缩放**：**高频保留，低频缩放，中间频率做平滑插值过渡。同时 YaRN 还会加入 attention scaling**来稳定长上下文下的注意力分布。
### 面试提醒

先说 Self-Attention 为什么需要位置编码，再对比三种方案。不要只背名字，要说清 RoPE 为什么成为主流。

## 5. 什么是大模型项目的分词器？原理是什么？

### 核心回答

**Tokenizer 是把人类文本转换成模型能处理的 token ID 序列的工具**。模型不认识字符串，只认识整数 ID。主流方案是子词分词，例如 BPE、SentencePiece/Unigram、WordPiece。
### 细节

- 字符级分词：词表小，但序列太长、语义弱。
- 词级分词：语义清晰，但词表巨大，容易 OOV（未登录词）。
- 子词分词：在字符和词之间折中，既控制词表大小，又能处理新词。
- BPE：**从小单元开始，不断合并最高频相邻片段，直到达到目标词表大小**。
- SentencePiece：常用于多语言模型，不依赖空格分词。
- **特殊 token：BOS、EOS、PAD、SEP，以及对话格式中的系统/用户/助手标记。**
### 面试提醒

回答 Tokenizer 时要说清“为什么需要它”：它是文本和模型整数世界之间的桥梁。再补充 token 计费和上下文窗口管理的工程影响。

## 6. 大模型是怎么训练出来的？
### 核心回答

大模型训练通常分为三个阶段：**预训练、SFT、对齐**。预训练决定基础能力和知识，SFT 让模型学会指令问答格式，对齐让模型更符合人类偏好和安全要求。
### 细节

| 阶段  | 目标          | 数据          | 作用           |
| --- | ----------- | ----------- | ------------ |
| 预训练 | 预测下一个 token | 海量无标注文本     | 学语言、知识、基础能力  |
| SFT | 学会按指令回答     | **指令-答案数据** | 从续写模型变成对话模型  |
| 对齐  | 更符合人类偏好     | 偏好数据、奖励信号   | 提升有用性、安全性、风格 |

预训练最消耗算力和数据，是能力天花板的主要来源。**SFT 质量比数量更重要**。对齐阶段常见方法包括 RLHF、DPO、GRPO 等。
### 面试提醒

记住一句话：预训练定天花板，SFT 给格式，对齐给价值观。面试时要说明每个阶段为什么不可替代。

## 7. 什么是 Scaling Law？大模型的涌现能力是怎么回事？

### 核心回答

Scaling Law 描述模型效果和**参数规模、训练数据量、训练算力**之间的可预测关系。模型规模、数据和算力提升后，loss 会按幂律下降。**涌现能力是指模型规模到达一定阈值后，突然表现出之前没有的能力**。
### 细节

- OpenAI 早期 Scaling Law 说明规模扩大能稳定提升性能。
- Chinchilla **强调参数和训练 token 要按合理比例配置**（1:20），而不是盲目堆参数。
- 一个常见结论是固定训练算力下，模型参数和训练 token 需要平衡。
- 涌现能力包括多步推理、上下文学习、跨语言迁移、代码理解等。
- **天花板：算力墙和数据墙  未来：合成数据，多模态数据，强化学习数据（用环境交互生产**）
### 面试提醒

回答 Scaling Law 时不要只说“大力出奇迹”。要强调参数、数据、算力三者的配比，以及它对模型训练和选型的工程启发。

## 8. 大模型微调方案有哪些？

### 核心回答

**微调不是第一选择，而是 Prompt、Few-shot、RAG 都解决不了时再考虑。微调方案可以从两个维度看：改哪些参数，以及学什么目标。常见方案包括全量微调、LoRA、QLoRA、SFT、DPO 等。**
### 细节

改哪些参数：

- 全量微调：更新全部参数，效果上限高，成本和风险也高。
- LoRA：**冻结原模型，只训练低秩旁路矩阵，成本低**。
- QLoRA：先把基础模型用**4-bit 量化（一种叫 NF4 的格式）**，在量化模型上做 LoRA

学什么目标：

- SFT：用指令-答案数据训练模型按指令回答。
- DPO：用偏好对训练模型更偏向好回答。
- RLHF/PPO：用奖励模型和强化学习做对齐，复杂但上限高。

LoRA 是方法，SFT 是目标，两者不是并列关系。可以用 LoRA 做 SFT，也可以用 LoRA 做 DPO。
### 面试提醒

面试时先说“微调是最后手段”。然后讲清两个正交维度：参数更新方式和训练目标。

## 9. LoRA 技术是什么？除了减少参数量还有哪些优点？

### 核心回答

**LoRA 的做法是：冻结原始权重 W 不动，在 W 旁边新增两个小矩阵 A 和 B（维度分别是 d×r 和 r×d，其中 r 远小于 d，通常 r=8 或 16），训练时只更新这两个小矩阵。推理时把 B·A 加回到 W 上，等价于一个全量微调过的模型，但训练时显存和算力开销是全量微调的几十之一。**
### 细节

LoRA 的优势：

- **参数少**：只训练低秩矩阵，不更新全量权重。
- **推理零开销**：训练后可以把 LoRA 权重合并回原模型权重。
- **部署灵活**：一个基础模型可以挂多套 LoRA，按场景切换。
- **降低灾难性遗忘：原始权重冻结，通用能力更容易保留。
- 训练更稳：可训练参数少，对**学习率等超参没那么敏感。
- **可组合：不同 LoRA 可以做合并或加权组合。

LoRA 和 Adapter 的区别之一是：Adapter 推理时通常还要走额外模块，而 LoRA 可以 merge 到原权重里。
### 面试提醒

不要只说“LoRA 省参数”。更完整的回答是：LoRA 成为 PEFT 主流，是因为它同时具备低成本、零推理开销、易部署和低遗忘风险。

## 10. SFT 之后有哪些 Post-Training？RLHF、DPO、GRPO、拒绝采样是什么关系？

### 核心回答

Post-Training 是 SFT 之后继续提升模型质量的一组方法，不是单一技术。SFT 让模型会按指令回答，但还需要进一步优化安全性、人类偏好、推理能力和回答质量。常见方法包括 RLHF、DPO、GRPO、拒绝采样、RLAIF。
### 细节

| 方法       | 核心思路                                      | 优点          | 缺点           |
| -------- | ----------------------------------------- | ----------- | ------------ |
| RLHF/PPO | **训练奖励模型**，再用 PPO 优化主模型，四个模型（**KL散度来限制**） | 效果上限高       | 工程复杂、训练不稳定   |
| DPO      | 直接用偏好对优化（**chosen- reject对**），不显式训练奖励模型   | 简单、稳定、开源常用  | 依赖偏好数据质量     |
| GRPO     | 用同题多回答的**组内相对优势（advantage**替代 Value Model | 省显存，适合可验证任务 | 更偏推理/数学/代码场景 |
| 拒绝采样     | 生成多个回答，筛出高分回答再 SFT                        | 简单直接        | 依赖筛选器质量      |
| RLAIF    | 用 AI 反馈替代人类反馈                             | 标注成本低       | 依赖强教师模型      |
### 面试提醒

先说 Post-Training 是上位概念，再说明 RLHF、DPO、GRPO、拒绝采样分别在流程中的位置。重点是它们常**组合，而不是互相替代。

## 11. DPO 和 PPO 的区别是什么？

### 核心回答

DPO 和 PPO 都用于 SFT 后的偏好对齐。PPO 是强化学习流程，需要**奖励模型、参考模型、策略模型和值模型**等组件；DPO 把带 KL 约束的 RLHF 目标改写成**偏好对上的监督学习损失，不需要显式奖励模型**，训练更简单稳定，只留下了policy + reference。
### 细节

PPO 流程：

- 收集人类偏好数据。
- 训练奖励模型。
- 用 PPO 让主模型生成更高奖励的回答。
- **用 KL 约束防止模型偏离参考模型太远。

DPO 流程：

- **输入 `(prompt, chosen, rejected)` 偏好对。
- 直接提升 chosen 的相对概率，压低 rejected 的相对概率。
- 不需要单独训练奖励模型。
- 工程实现更接近监督学习。

类比：

- PPO：先训练裁判，再训练选手。
- DPO：直接拿比赛录像告诉选手哪个动作更好。
----
**GRPO 相比 PPO 的关键改动，就是砍掉了 Value Model / Critic，不再额外训练价值函数，而是对同一个问题采样多条回答，用组内 reward 的均值和标准差做归一化，计算每条回答的相对优势。**
### 面试提醒

一句话：两者目标一致，都是偏好对齐；PPO 走强化学习和奖励模型，**DPO 省掉奖励模型，把对齐训练简化成监督学习。

## 12. 大模型生成文本时有哪些解码策略？

### 核心回答

解码策略解决的是：模型每一步输出一个**词表大小的概率分布后**，如何选择下一个 token。主流策略分为**确定性策略和随机采样策略**。确定性策略包括贪心和 Beam Search，随机策略包括 Temperature、Top-K、Top-P。
### 细节

| 策略              | 思路               | 优点             | 缺点           | 适用场景          |
| --------------- | ---------------- | -------------- | ------------ | ------------- |
| Greedy          | 每步选最高概率 token    | 稳定、可复现         | 易重复、缺多样性     | 分类、抽取、代码等精确任务 |
| Beam Search     | 保留多条候选路径，选总概率最高  | 适合翻译等有明确最优答案任务 | 对开放生成容易无聊、重复 | 传统机器翻译        |
| **Temperature** | 调整概率分布尖锐程度       | 控制随机性          | 高温容易跑偏       | 通用采样控制        |
| Top-K           | 只从前 K 个 token 采样 | 截断长尾           | K 固定不够自适应    | 辅助采样          |
| **Top-P**       | 从累计概率达到 P 的候选集采样 | 自适应候选池         | 需要调参         | 对话、写作、开放生成    |

Beam Search 在传统翻译任务很强，但在 LLM 开放生成中不常用，因为它会偏向高概率但无聊的回答。
LLM API 通常都会提供 **Temperature + Top-P**这类采样参数，但默认值各家不完全一样，有的默认更稳定，有的默认更开放。更稳的工程表达是：精确任务（代码、数学、信息抽取）用 **Temperature=0 或低温来提高可复现性；对话/创意任务用较高 Temperature 配合 Top-P 平衡多样性和质量。**
### 面试提醒

精确任务用低温或贪心，创意写作用较高温度和 Top-P。Beam Search 在 LLM 聊天和写作场景里通常不是首选。

## 13. Temperature、Top-P、Top-K 分别是什么？怎么设置？

### 核心回答
Temperature 控制的是分布的锐度。数学上 Temperature T 的作用是把每个 logit 除以 T 再做 softmax：
- T=0：等价于贪心（永远选最高）
- T=1：用模型原始分布采样
- T<1（比如 0.5）：分布变尖锐，更倾向高概率词
- T>1（比如 1.2）：分布变平坦，更倾向探索低概率词

**Top-K 是固定截断**：每步只从概率最高的 K 个 token 里采样，后面全部丢弃

**Top-P（Nucleus 采样）是自适应截断：从高到低累加概率，超过阈值 P（比如 0.9）就停，从这个「核」里采样**。Top-P 的好处是候选集大小会根据分布形状自动调整，分布尖锐时候选集小（几个词就累加到 0.9），分布平坦时候选集大。
### 细节

推荐设置：

| 场景 | Temperature | Top-P | Top-K |
| --- | --- | --- | --- |
| 代码、SQL、结构化抽取 | 0-0.2 | 默认或 0.9-1.0 | 通常不动 |
| 普通问答、客服 | 0.3-0.7 | 默认或 0.9 | 通常不动 |
| 创意写作、头脑风暴 | 0.8-1.2 | 0.9-1.0 | 通常不动 |
| 严格 JSON 输出 | 0 或低温 | 默认 | 通常不动 |

工程经验：

- **一次主要调一个参数。
- **通常先调 Temperature，Top-P 保持默认。
- 不要同时大幅调整 Temperature 和 Top-P，否则难以判断效果来源。
	先只调 temperature，top_p 保持默认或 0.9~1.0，top_k 不设置
### 面试提醒

一句话：Temperature 调分布锐度，Top-K 固定截断，Top-P 自适应截断。实际项目里 Temperature 最常调，Top-P/Top-K 多数保持默认。

## 14. KV Cache 是什么？Prompt Caching 的原理是什么？

### 核心回答

KV Cache 是单次推理内的缓存优化，缓存历史 token 的 K/V，避免每生成一个 token 都重新计算所有历史上下文。Prompt Caching 是跨请求复用相同前缀的 KV Cache，用于降低重复 Prompt 的成本和延迟。
### 细节

**KV Cache：
K 和 V 矩阵缓存在 GPU 显存里，每次新 token 只算自己的 Q、K、V，然后跟缓存的 K/V 做 attention，把总计算量从 O(N³) 降到 O(N²)

---
- 自回归生成每次只生成一个新 token。
- 如果每步都重算历史 token 的 K/V，会极其浪费。
- KV Cache 把历史 token 的 K/V 存在显存中。
- 新 token 只需要计算自己的 Q/K/V，再和缓存交互。
- 它是现代 LLM **推理的基本盘。

**Prompt Caching：

- 如果多个请求共享相同前缀，例如 **system prompt**、固定工具说明、**Few-shot 示例**、**基于同一份长文档的多次问答**可以复用前缀 KV Cache。
- **第一次请求计算并缓存，后续请求命中后只算新增部分。
- 价值是降低首 token 延迟和输入 token 成本。
- 这是KV Cache的工程化延伸

| 对比项  | Claude / Anthropic                                        | OpenAI                                        |
| ---- | --------------------------------------------------------- | --------------------------------------------- |
| 缓存方式 | **显式缓存**，需要用 `cache_control` 标记缓存断点                       | **自动缓存**，从 1024 tokens 开始，系统自动识别重复的 Prompt 前缀 |
| 控制粒度 | 更细，可以指定“缓存到哪一段为止”                                         | 更省心，但控制粒度较粗                                   |
| 缓存对象 | 从 Prompt 开头到 `cache_control` 标记处的内容                       | 和历史请求相同的最长 Prompt 前缀                          |
| 命中条件 | 缓存断点前内容必须完全一致                                             | Prompt 前缀必须一致                                 |
| 适合场景 | 长文档、工具定义、few-shot、固定 system prompt                        | 固定长 Prompt、多轮对话、代码库上下文                        |

工程要点：

- **固定内容放前面，动态内容放后面。
- **前缀只要差一个字符就可能缓存 miss。
- 低流量或前缀不稳定时，Prompt Caching 收益有限。
### 面试提醒

核心关系：**KV Cache 是单次推理内复用，Prompt Caching 是跨请求复用。两者底层机制相通，时间尺度不同。

## 15. 大模型量化是什么？INT8/INT4/AWQ/GPTQ 怎么选？

### 核心回答

**量化的核心：映射连续到离散，模型权重从 FP16/FP32 等高精度浮点数映射到 INT8、INT4 等低精度表示，从而减少显存占用、提升推理速度**。
### 细节

| 方法        | 核心思路                           | 适合场景                      |
| --------- | ------------------------------ | ------------------------- |
| INT8      | 8 bit 量化                       | 精度损失小，损失**<0.5%**，生产稳妥    |
| INT4      | 4 bit 量化                       | 显存大幅下降，部署甜蜜点，**损失精度1-3%** |
| **GPTQ**  | 逐层量化 + 误差补偿                    | 追求较好精度和低位压缩               |
| **AWQ**   | 激活感知，保护重要权重                    | 推理速度和效果较稳                 |
| QLoRA/NF4 | **面向权重分布的 4 bit 量化** + LoRA 微调 | 消费级 GPU 微调                |
| GGUF      | llama.cpp 常用文件格式               | 本地/边缘部署                   |

> GPTQ 和 AWQ 都是大模型 INT4 权重量化方法。GPTQ 的思路是用校准数据估计量化误差，并利用近似二阶信息对误差进行补偿，所以它更像是“最小化量化后重构误差”；AWQ 的思路是观察 activation，认为和大激活值相乘的权重更重要，因此通过通道缩放保护这些关键权重，减少量化损失。简单说，GPTQ 关注“误差怎么补偿”，AWQ 关注“哪些权重更重要”。
**注意：AWQ/GPTQ 是量化算法，GGUF 是文件格式，不是同一层概念。

|类型|总位数|指数位|尾数位|特点|
|---|--:|--:|--:|---|
|FP32|32 bit|8|23|精度高，显存大|
|FP16|16 bit|5|10|精度比 BF16 高，但范围小|
|BF16|16 bit|8|7|范围接近 FP32，训练更稳定|
- 不同算法的差别，在于**怎么算 scale 和 zero_point**、**怎么处理 outlier（异常大的权重值）**、**怎么补偿量化误差**。
- **对称量化**假设数据围绕 0 对称分布，所以不需要 zero_point，公式简单、硬件友好，通常适合权重量化。
- **非对称量化**用于数据范围不对称的情况，比如 ReLU 后的激活值整体偏正，需要通过 zero_point 把浮点范围和整数刻度对齐，能减少量化误差，但实现更复杂。
### 面试提醒

选量化方案要**先看推理框架和硬件 kernel 支持**，再做业务评测。数学、代码、长上下文任务对量化更敏感，不能只看通用分数。

## 16. 如何写好 Prompt？Prompt 工程实践经验有哪些？

### 核心回答

好的 Prompt 要明确**角色、任务、上下文、输出格式和示例**。Prompt 也是工程问题，需要**测试集、迭代和回归验证**。
### 细节

Prompt 五要素：

- Role：设定模型角色。
- Task：明确任务目标和边界。
- Context：**补充业务背景、输入材料、约束。
- Format：**约定输出结构，尤其是 JSON、表格、字段名。
- Examples：**提供 Few-shot 示例，让模型模仿。

进阶技巧：

- 用 **XML/标签包裹不同输入块，减少结构混淆。
- 复杂任务可让**模型先分析再回答。
- 对结构化输出要给 schema 和反例。
- 对**长 Prompt 可考虑压缩和缓存。

工程实践：

- 建 30-50 条覆盖常见和边缘情况的测试集。
- 每次只改一处 Prompt，避免多变量干扰。
- 每次修改都跑回归测试。
### 面试提醒

不要把 Prompt 工程说成“写得详细一点”。真正的工程化做法是：定义结构、约束输出、给示例、建测试集、持续迭代。

## 17. 什么是 CoT？为什么有效？有什么局限？

### 核心回答

CoT 是 Chain of Thought，让**模型先分步推理再给答案**。它有效的原因是**模型按 token 生成，先写出中间步骤相当于给模型一张草稿纸，后续答案可以基于前面的推理上下文生成**。
### 细节

两种常见形式：

- **Zero-shot CoT**：直接加“让我们一步步思考”这类触发语。
- **Few-shot CoT**：给几个带完整推理过程的示例，让模型模仿。

优点：

- 提升多步推理、数学、逻辑任务的准确率。
- 让中间过程更可检查。

局限：

- **消耗更多 token，增加成本和延迟。
- **推理链本身可能出错，错误会向后传播。
- **对纯记忆类问题帮助不大。
- 面向用户的产品不一定展示完整推理链，通常展示简要依据即可。

### 面试提醒

CoT 适合多步推理，不适合所有问题。

## 18. 大模型为什么会出现幻觉？怎么缓解？

### 核心回答

幻觉是指模型生成了流畅、合理但实际错误的内容。根因是 LLM 本质是续写下一个概率最大的token，不是数据库。
### 细节

幻觉来源：

- **训练数据问题**：互联网语料有错误、过时、矛盾信息。
- **生成机制问题**：模型按概率续写，不是真的查事实。
- **对齐副作用**：训练中**人类可能偏好自信回答，导致模型不擅长拒答。

幻觉类型：

- **事实性幻觉**：编造不存在的人物、事件、引用。
- **推理性幻觉**：推理链错误或前后矛盾。
- **上下文不一致**：违反用户给定条件。

缓解方案：

- **训练层**： **SFT 数据里加入大量「拒答样例」**，做校准训练：让奖励模型学到「错误且自信」要严厉扣分。
- **推理层**：降低温度、分步分析、Self-Consistency、约束输出。
- **系统层**：RAG、事实核查、强制引用来源、答案后处理。
### 面试提醒

幻觉不可能彻底消除，因为它是概率生成机制的固有副产物。工程目标是降低发生率，并让用户能识别和追溯。

## 19. MoE 混合专家模型是什么？为什么 DeepSeek、Qwen 等模型会用 MoE？

### 核心回答

MoE 是 Mixture of Experts，**核心是把 Transformer 中的 FFN 层替换成多个专家网络，再用 Router 为每个 token 选择少数专家参与计算。它的设计哲学是“总参数大，激活参数小”。**
### 细节

核心组件：

- **Experts**：多个并行专家网络，各自学习不同能力方向。（➕共享专家）
- **Router**：为每个 token 选择 Top-K 专家。
- **负载均衡**：防止 Router 总是选择少数热门专家。

优势：

- 训练容量大：总参数多，能承载更多知识。
- **推理成本可控**：每个 token 只激活少量参数。
- 扩展性强：增加专家数比无限加深模型更灵活。

挑战：

- **训练不稳定，容易专家不均衡。
- **显存仍要加载总参数，不是只加载激活参数。
- 分布式推理有 All-to-All 通信开销。
- 热门专家可能成为吞吐瓶颈。
### 面试提醒

要说清一句反直觉但关键的话：**MoE 的推理计算量看激活参数，但显存通常要看总参数**。它省的是计算，不一定省总显存。
**DeepSeek V3 用 256 个专家、激活 9 个（Top-8 routed + 1 shared），671B / 37B、激活率 5.5%**

## 20. 大模型部署有哪些主流方案？vLLM、TGI、llama.cpp、SGLang 怎么选？

### 核心回答

大模型部署框架解决的是如何在**固定硬件上更省显存**、**更高吞吐**、**更低延迟**地服务**并发请求**。主流方案包括 vLLM、SGLang、TGI、llama.cpp、TensorRT-LLM。
### 细节
![](../_assets/Review-%E5%A4%8D%E4%B9%A0%E6%80%BB%E7%BB%93/Pasted%20image%2020260612231106.png)
#### vLLM：
- **Continuous Batching（连续批处理） 是「请求异步加入和退出，每个 token 步骤动态组 batch」。
- **PagedAttention 的原理是把推理阶段的 KV Cache 像操作系统分页一样切成固定大小的 block，存放在 HBM 中不要求物理连续，再通过 block table 映射逻辑 token 到物理 block，从而减少显存碎片和预分配浪费，提高并发吞吐。**
#### SGLang:
- **RadixAttention 的原理是用 Radix Tree（前缀树）管理不同请求的 KV Cache，把相同 prompt 前缀对应的 KV 复用起来，避免重复 prefill，从而降低延迟和显存/计算开销。**

#### 部署痛点：
- KV Cache 占显存。
- 批量调度影响吞吐。
- 长上下文容易显存碎片。
- MoE 部署比 Dense 模型更复杂。
- 量化和 kernel 支持差异很大。

## 21. 大模型能力评测指标有哪些？
### 核心回答

大模型评测分为**通用 Benchmark 和业务评测**。MMLU、HumanEval、GSM8K、MATH、SWE-bench 等可以衡量模型能力区间，但**真正可靠的是基于业务真实数据构建的测试集**。
### 细节

常见 Benchmark：

- **MMLU**/**MMLU-Pro**：综合知识和推理。
- **HumanEval/MBPP**：代码生成能力。
- **SWE-bench**：真实软件工程修复能力。
- **GSM8K/MATH/GPQA**：数学和科学推理。
- **MT-Bench/Arena**：更偏对话和 Agent / Tool Use 能力。
- **HELM/LiveBench**：综合或持续更新评测。

业务评测方法：

- 从真实用户请求中采样 50-200 条。
- 人工标注期望答案或评分标准。
- 客观任务用程序自动验证。
- 主观任务可用 LLM-as-Judge，并抽样人工校准。
- 每次换模型、改 Prompt、改工具链都跑回归。

线上指标：

- 用户满意度。
- 任务完成率。
- 点踩率。
- 会话放弃率。
- 转人工率。
### 面试提醒

不要迷信公开榜单，因为可能有**数据污染**，也不一定代表业务效果。最终要看**业务测试集和线上指标**。
**数据污染**问题的应对方向：避免用公开 Benchmark 直接当训练集、用 LiveBench 这种「持续更新题库」的评测、用业务真实数据做评测。

## 22. 对比使用过哪些主流大模型？项目最终选哪个？为什么？

### 核心回答

模型选型不是看排行榜最高，而是看**合规、成本、延迟、能力特征和业务需求**是否匹配。工程上也不一定只用一个模型，常见做法是**Model Routing：不同节点使用不同模型**。
### 细节

选型维度：

- 合规：是否允许数据出境，是否能私有化部署。
- 能力：推理、代码、中文、长上下文、工具调用、结构化输出。
- 成本：输入输出 token 单价、缓存收益、并发费用。
- 延迟：首 token 延迟、整体响应时间、吞吐。
- 稳定性：API 可用性、限流、错误率。
- 生态：SDK、工具调用、函数调用、部署框架支持。

模型路由思路：

- 调度、结构化输出、Tool Use：选指令遵循和 JSON 稳定的模型。
- 高频摘要、清洗、分类：选低成本高吞吐模型。
- 复杂推理、代码、长文本：路由到更强但更贵的模型。
- 敏感数据链路：优先选本地或合规可控模型。
### 面试提醒

回答模型选型时要体现工程约束。技术能力不是唯一标准，ToB 项目里合规、成本、稳定性往往比榜单排名更重要。

---

| 对比项      | FlashAttention                                             | PagedAttention                                       | RadixAttention                                       |
| -------- | ---------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------- |
| 一句话原理    | **把 attention 计算分块搬到片上 SRAM 里算，避免显式保存完整 attention matrix** | **把 KV Cache 切成固定大小 block，用 block table 管理，不要求物理连续** | **用 Radix Tree 管理共享 prompt 前缀，把相同前缀的 KV Cache 复用起来** |
| 主要优化对象   | Attention 计算过程                                             | KV Cache 的显存管理                                       | KV Cache 的跨请求复用                                      |
| 解决什么问题   | 标准 attention 需要生成 (N \times N) attention matrix，显存读写大      | 推理时 KV Cache 预分配浪费、显存碎片、并发低                          | 多个请求有相同前缀时，重复 prefill 浪费算力                           |
| 核心技术     | Tiling / Blocking、Online Softmax、减少 HBM 读写                 | 固定大小 block、block table、非连续显存分配                       | Radix Tree / 前缀树、prefix matching、KV Cache 共享         |
| 主要收益     | attention 算得更快、更省显存                                        | KV Cache 存得更省，提高并发吞吐                                 | 相同前缀不重复算，降低 prefill 延迟和成本                            |
| 典型场景     | 长序列训练、长上下文推理                                               | vLLM 高并发推理服务                                         | 多轮对话、Agent、few-shot、长 system prompt、批量请求共享前缀         |
| 关注阶段     | 训练和推理都能用                                                   | 主要是推理阶段                                              | 主要是推理阶段，尤其 prefill 阶段                                |
